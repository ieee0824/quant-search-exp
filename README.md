# quant-search-exp

小さなDNNを学習し、同じ学習済み重みから複数の量子化モデルを作って比較する実験。出発点は[「FP6から考えるLLM量子化: 限られたbitをどこに配るか」](https://blog.ast.moe/blog/2026-09-24/)にある、**保存bit数が同じでも、表現方法や精度の配分でモデルの挙動は変わるのか**という問い。

現在はRustの初期ひな形のみで、学習・量子化・評価は未実装。

## 最初の実験

1. Fashion-MNISTを使い、入力784 → 隠れ層256 → 隠れ層128 → 出力10の全結合ネットワークを学習する。活性化関数はReLUとする。
2. 学習済みモデルの重みをFP16で保存し、これを基準モデルとする。学習時の勾配計算や累積には、数値安定性のためFP32を使ってよい。量子化候補ごとに再学習はしない。
3. 同じ重みから以下の候補を作る。最初は重みのみを量子化し、biasとactivationの精度は揃える。

   | 候補 | 確かめること |
   | --- | --- |
   | FP16 | 量子化前の精度と推論速度 |
   | 一律FP6 E3M2 | 指数に多くbitを割く場合の基準 |
   | 一律FP6 E2M3 | 仮数に多くbitを割く場合との差 |
   | blockごとにE3M2/E2M3を選択 | 同じ6bitの値でも、分布に応じた形式選択が効くか |
   | 形式を固定し、scaleや丸め方を探索 | 推論形式を増やさず、量子化時の探索だけで改善できるか |

4. blockはまず連続する重み32個とし、blockごとに共有scaleを持たせる。形式選択は検証データで行い、形式を示す情報もモデル容量に計上する。scaleの符号化と端数処理は実装時に固定し、全候補で共通にする。

## 比較条件

- データを学習用・検証用・テスト用に分ける。量子化候補の選択には検証用だけを使い、テスト用は最終比較まで使わない。
- モデル構造、学習済み重み、データ分割、乱数seed、推論環境を全候補で揃える。
- 分類精度と交差エントロピー損失を測る。加えて、FP16モデルからの出力logitのずれを測り、正答率だけでは見えない変化を確認する。
- 重み本体だけでなく、共有scale、形式タグ、paddingを含めた実際のファイル容量と平均bit/weightを記録する。
- 推論時間は同じマシンで測り、量子化値の展開とscale適用も含める。容量が小さいだけで高速とは判断しない。
- 少なくとも複数の学習seedで結果を取り、平均とばらつきを報告する。

形式選択や探索を増やすほど検証データへ合わせ込みやすくなる。候補の順位はテストデータでも確認する。この小さな画像分類モデルで得た結果を、そのままLLMの量子化性能へ一般化しない。

## 実装の順序

1. データ読み込み、DNNの学習、FP16基準モデルの保存と再読み込み
2. FP16基準モデルのテスト精度を再現できる評価器
3. FP6 E3M2/E2M3の符号化・復号と、一律形式での量子化
4. blockごとの形式選択と、scale・丸め方の探索
5. 容量、予測品質、推論時間を同じ条件で記録する比較レポート

この順序で、まず一律FP6の基準を作り、その後に選択や探索を一つずつ加える。混合bit幅や座標変換は、その結果を見てから追加する。
